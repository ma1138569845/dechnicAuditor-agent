# 折标系数与综合能耗口径（2026-09-02 实证）

## 权威系数（DB37/T 2672-2019 附录B）

| 能源 | 系数 | 单位 |
|---|---|---|
| 电力 | 0.31 | kgce/kWh（供电煤耗法，等价） |
| 热力 | 0.03412 | kgce/MJ = 34.12 kgce/GJ |
| 天然气 | 1.2143 | kgce/m³ |
| 汽油 | 1.4714 | kgce/kg |
| 柴油 | 1.4571 | kgce/kg |
| 水 | — | 不折算（附录B 无水折标系数，不计入综合能耗） |

## 综合能耗口径（5.3.3 人均综合能耗）

综合能耗 = 电×0.31 + 供热量(GJ)×34.12 + 气×1.2143 + 油×1.4714；**水不计入**。

烟台法院验证锚点（351 人，与正式报告逐位对齐）：
2023 = 1559.48 / 2024 = 1334.35 / 2025 = 1293.60 kgce/(p·a)。
算不出此值 → 先查系数链，勿调数据。

## DB 系数坑

1. **heat 单位归一（kgce/GJ ↔ tce/GJ）**：energy_main 热力(50) 的
   standard_coal_coefficient 存 **34.12（kgce/GJ）**，而指标计算用
   **0.03412（tce/GJ）**。pg_collector 写 coefficients dict 前已归一
   （coeff_type=='heat' 且值>1 时 ÷1000）；自行取数勿把 34.12 当 0.03412
   或反之，否则供暖能耗/综合能耗差 1000 倍或 0.1%。
2. **DB 气系数 1.33 是错值**：标准附录B = 1.2143 kgce/m³。法院项目已修
   （8 条含三版本，备份 db_gas_coeff_fix_20260902.json）；其他项目遇 1.33
   同样按 1.2143 修正或向用户确认。
3. **lookup_coefficient_from_db 无 customer 过滤（⚠️ 跨项目系数污染）**：
   indicators.py 的系数 Layer1 按 energy_code 全局 ORDER BY id DESC，会取到
   **别的项目**的系数（实证：法院 heat 拿到别家 0.0341 而非 0.03412，
   供暖能耗偏差 65~103 kgce/年；water 拿到别家 0.7143 原煤系数）。正常链路
   靠 pg_collector 把本项目系数持久化进 coefficients dict（dt=1/4/5 实物量
   记录统一记录），get_coefficient 优先读 dict 再回退三层兜底——因此
   **pg_collector 的系数持久化必须覆盖 dt=4（热力+供暖电）与 dt=5（油）**，
   漏掉任何一类都会让该类能源走 DB 全局查询被污染。
4. **is_valid_coefficient 只判 >0**：34.12 会通过校验直接存入——单位归一必须在
   写入前做（impl 已做），不能依赖校验拦截。

## 修复链路回顾（法院）

气系数 1.33→1.2143（8 条三版本）＋heat 归一后：
供暖能耗 2023/2024/2025 = 224,367 / 159,202 / 134,999 kgce；
人均综合能耗与正式版完全对齐（1559.48/1334.35/1293.65）。
