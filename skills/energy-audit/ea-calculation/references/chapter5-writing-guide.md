# 第5章生成逻辑（v2.10）

## 结构

```
总述段: "为全面准确分析{unit}用能情况，此次审计选取{year_range}完整年周期内{energy_types}等用能数据..."

5.1  能源资源消费/消耗概况
  - 一句话概述: "{unit}主要用能类型包括电、天然气、水。" ← 不要多段LLM文本
  - 图5.1 能源流向图（graphviz全动态）

5.2  能源资源消耗/消费数据（按用能类型动态生成H3）
  5.2.1 用电情况分析 → 表5.2 逐年用电消耗量 + 趋势描述
  5.2.2 用水情况分析 → 表5.3 逐年用水消耗量
  5.2.3 用气情况分析 → 表5.4 逐年用气消耗量（仅当有数据）
  5.2.N 能源资源费用分析 → 逐年费用表 + 费用合计表

5.3  能耗资源消耗/消费指标
  5.3.1 单位建筑面积非供暖能耗 → 表5.{next_table}   (公式+DB37对标)
  5.3.2 常规用能系统单位建筑面积电耗 → 表5.{next_table+1}
  5.3.3 人均综合能耗 → 表5.{next_table+2}
  5.3.4 人均取水量 → 表5.{next_table+3}

5.4  建筑能耗基准
  用量基准 → 表5.{next_table+4}
  费用基准 → 表5.{next_table+5}
```

## 各节规则

### 总述段
- 自动生成: 描述审计周期 + 用能类型 + 计算目的
- 格式: "为全面准确分析{unit}用能情况和用能规律，此次能源审计工作选取{year_range}完整年周期内{types}等用能数据，并根据近三年总用能及各项用能数据进行计算分析。"

### 5.1 极简模式
- **只有一句话概述 + 能源流向图**
- 不要饼图、趋势柱状图、能源结构表（这些都已被移除）
- 概述格式: `{unit_short}主要用能类型包括电、天然气、水。`
- 能源流向的细节由流向图本身表达，不需要长文本描述

### 5.2 动态分节
- 遍历 `energy_types`，**只有有数据的类型**才生成 H3 小节和表
- 能源数据从 `yd_objects` (YearlyEnergyData 列表) 读取
- 小节内容不是单行趋势，需要完整分析段落:
  1. **逐年消耗量表**: 1行(项目+各年份值)
  2. **趋势方向**: "从XX年至XX年，XX年用电量呈增长/下降/平稳趋势"
  3. **统计数据**: "三年平均XX量为{avg}，最高为{max}，最低为{min}"
  4. **原因推断**: 增长 → "可能包括用能设备增加、用能时间延长或能效水平下降等因素"
               下降 → "可能得益于节能改造措施的实施、用能管理水平的提升以及部分老旧设备的更新淘汰"
- 趋势判断基准: v_last > v_first × 1.05 = "增长", v_first > v_last × 1.05 = "下降", 否则 "总体保持平稳"
- 费用分析固定最后一节，仅当至少一项费用 > 0 且 >= 1 年有数据才生成

### 5.3 指标
- 四项指标逐一生成: 公式描述 + 指标表 + 定额对标
- 指标表统一为**行列转换（转置）样式**：指标项为行、年份为列
  - 首列: 项目（公式中各变量的基础数据行 + 指标值行 + 约束/基准/引导值行 + 评价行）
  - 其余各列: 每个统计年份一列（2022年/2023年/2024年）
  - 对标值（约束值/基准值/引导值，取水为通用值/先进值）各占一行，三年数值相同仍逐年填充
- 调用 `resolve_benchmark(institution_type, metric)` 取值
- 评价分级: 低于引导值 > 低于基准值 > 低于约束值 > 高于约束值

### 5.4 基准
- 调用 `calc_baseline(yd_objects)` 计算三年基准
- 用量基准表: 能源类型 / 基准值 / 单位 / 计算方法
- 费用基准表: 费用类型 / 基准值(万元) / 计算方法
- 计算方法: 三年均值(波动≤±10%) / 最近一年(波动>±10%)

## 动态表号

5.2 生成的表数随 energy_types 数量变化。`section_num` 从 1 开始，每个能源类型 +1。

计算逻辑:
```python
section_num = 1
for et_key, et_title, unit, _ in energy_type_sections:
    if has_data:  section_num += 1
# 5.2 表号: 表5.{1+1} ~ 表5.{section_num}
# 费用分析表号: 表5.{section_num+1}, 表5.{section_num+2}
next_table = section_num + 3  # 5.3 起点
```

- 莘县(电/水/气 3型): 表5.2~5.6(5.2节) + 表5.7~5.12(5.3+5.4)
- 某单位(电/水 2型): 表5.2~5.4(5.2节) + 表5.5~5.10(5.3+5.4)
- 无能耗数据: 直接跳转, 显示提示语

## 能源流向图

### 工具
- **graphviz** (非 matplotlib)
- 函数: `tools/energy_audit/energy_flow_chart.py::draw_energy_flow_diagram()`
- 参数: `energy_types`, `equipment`, `unit_name`, `output_path`

### 系统依赖
- Windows: `winget install Graphviz.Graphviz`
- macOS: `brew install graphviz`
- Linux: `apt install graphviz`
- 安装后确保 `dot` 在 PATH 中
- 代码自动探测 `C:\Program Files\Graphviz\bin` 并加入 PATH

### 设计规则
- 三层结构: 能源输入(圆角矩形) → 用能系统(直角矩形) → 终端设备(直角矩形)
- 颜色编码: 电力=橙色(#E65100), 水=蓝色(#1565C0), 天然气=绿色(#2E7D32), 供暖=红色(#C62828), 油=灰色
- 实线=主要能源流, 虚线=辅助能源流(如水→空调冷却塔)
- **全动态**: 根据 energy_types 决定源节点, 根据 equipment 决定终端节点
- 无设备清单时使用内置默认终端(风冷冷水机组/分体式空调/灯具照明等)

## 关键 Pitfalls

1. **占比计算必崩**: `type_tce` key 是英文, 用中文 `row[0]` 去 `.get()` 返回0
   修复: `for i, et in enumerate(energy_types): rows[i][-1] = f"{type_tce[et]/sum_tce*100:.1f}%"`
2. **表号冲突**: 5.2和5.3和5.4共用动态表号, 不可硬编码表5.3~表5.8
3. **5.1不要饼图**: 饼图和趋势柱状图已从5.1移除, 不要恢复
4. **graphviz未安装**: 系统需安装 graphviz 二进制, pip graphviz 只是 Python wrapper
5. **energy_data 缺失**: 直接 print 提示 + return, 不生成第5章
