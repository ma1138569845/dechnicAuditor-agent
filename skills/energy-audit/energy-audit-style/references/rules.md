## 跨章论证链（原 argument-logic）

从法院/医院/学校样板报告中提取。每条规则 = 输入（需要什么数据）→ 推理（动作序列，
动词固定：calculate/compare/identify/explain/cite/propose）→ 输出（段落/表/图/评价短语）
→ 触发（什么条件写、缺数据怎么办）。

### 1. 全报告主论证链

```
能源现状数据 → 识别特征/异常 → 解释原因 → 对照定额评价 → 找出节能空间
→ 提出措施 → 估算节能率 → 结论汇总
```

- 第1-4章：铺垫（目的/概况/管理/计量）——回答"审计谁、怎么审"。
- 第5章：定量（消费/指标/基准）——回答"用多少、达标吗"。
- 第6章：定性（分系统）——回答"各系统怎么用的、有什么特点/问题"。
- 第7章：转化（问题→措施）——回答"哪里能省、怎么省、省多少"。
- 第8章：收敛（结论）——回答"总体评价+问题+建议"。

### 2. 分章论证链

#### 第1章 执行概要

- 1.1 审计目的：
  - 输入：委托方、被审计单位、审计机构。
  - 推理：cite（能源审计法定定义段）→ 说明委托关系。
  - 输出：定义段（标准原文，类型无关）+ 委托关系句。
  - 触发：必写；定义段为固定文字。
- 1.2 审计范围：
  - 输入：院区/建筑清单、审计期数据基础、指标类型。
  - 推理：cite（范围=全部用能系统+主要指标清单）。
  - 输出：范围段（含建筑清单【以院方最终核定为准】）+ 数据基础段 + 指标清单段。
  - 触发：必写；建筑明细不确定时加核定备注，不删范围。
- 1.3 审计周期（三段式，对齐正式报告）：
  - 输出：审计时间（create_time~生成时间）/ 审计期（audit_year）/ 基准期（reference_year）；
    格式 `YYYY年M月—YYYY年M月`（全角—）。
  - 触发：必写；勿写成两行旧口径。
- 1.6 审计依据：
  - 推理：cite（国标+省级规章+地方供热办法+机构类型专属标准）。
  - 输出：固定标准清单（约 20 余条，⚫ 开头逐条列）；医院追加 DB37/T 2673 与
    DB37/T 4452，学校/机关按各自定额标准追加。
  - 触发：必写；地方供热办法必须 web_search 验证后填入，禁止字符串替换。

#### 第2章 概况

- 2.1 基本情况：
  - 输入：basic_situation 直取优先 → 序列（全称→简称→行政归属→地址→性质→
    内设→人员）；缺失字段可 web_search 补文字事实，**数字禁查**。
  - 推理：cite（职能/等级/性质）→ 描述运行特征（医院：全天候+特殊用能）。
  - 输出：概况段 + 图2.1 外观照片（段落后紧跟）。
  - 触发：必写；用能人数注明出处口径（如【取自院方填报的能耗统计数据】）。
- 2.2 建筑物概况：
  - 输入：建筑清单（名称/地址/功能/面积/层数/结构/冷热源/末端/给水/热水）。
  - 输出：每栋一张 4 列键值对表（表2.1，无表头行、全表不加粗；字段与顺序按 `chapter-guides-1-4.md` §7 v4.0）+ 缺项【待补充】+ 表注（面积来源口径）。
  - 触发：有建筑数据才写；面积取自公开资料时表注"以院方核定为准"。
- 2.3 能源资源利用情况：
  - 输入：用能类型清单。
  - 推理：identify（各品种用途构成）→ explain（特殊用能识别）。
  - 输出：用途构成段 + 主要用能设备清单（缺→【待补充】）。
  - 触发：有数据才写；用途细分数据缺失时标注，不编。

#### 第3章 管理状况

- 输入：管理组织/方针/目标/节能荣誉/制度/痛点。
- 推理：cite（落实节能国策、机构设置）→ 列出职责条目 → 方针目标分层
  （管理与意识目标/重点系统节能目标）。
- 输出：3.1 职责段（职责 1/2/3…）+ 3.2 方针目标（一、二、三级列）+ 3.3 成效
  与问题（成效段+问题段，问题来自实际数据如"未建设能耗监测系统"）。
- 触发：es（energy_saving）无记录时走模板降级；照片（节能减排标识）可嵌。

#### 第4章 计量及统计

- 4.1 计量体系：
  - 输出：GB/T 29149-2012 六条配备原则固定文字 + 单位类型适配句（医院：数据中心/
    手术室/消毒供应等特殊功能区及洗衣房/食堂应单独计量）。
  - 触发：必写；4.1 为类型无关固定文字。
- 4.2 计量器具配备及管理：
  - 输入：metering 字段（监测系统/分项/分户/表计数量/独立计量）。
  - 推理：compare（配备 vs 标准要求）→ identify（缺项：未分项/未分区/未独立计量）。
  - 输出：配置段（已有什么+缺什么）+ 表4.1 计量器具配备清单 + 图4.1 计量器具照片。
  - 触发：**只写数据支持的缺项**，已有独立计量的禁止再问用户、禁止写成缺失。
- 4.3 能源资源统计成效及问题（原「4.3 统计情况」已废止并入本节）：
  - 输入：4.2 算出的 `has_ok`/`has_no`/`eqs` + 监测系统 + 现场三状态。
  - 输出：成效句（无字段，缺了问用户）→ 问题句（一是…二是…三是… + 后果：难以
    精准挖掘用能不合理原因及节能潜力点）→ 统计粒度句（统计周期非"日/实时"时）。

#### 第5章 消费/指标分析

- 5.2 消耗数据（按能源品种分节）：
  - 输入：三年用量+费用+逐月数据；+ 设备与系统形式（buildings 的冷源/热源/末端、equipment 台账）；
    + 现场事件（新楼投用/区域停用/改造工程，须有采集字段或用户书面确认）。
  - 推理：①identify 用途构成 ②三年数值段 ③图（趋势/逐月/费用占比）
    ④compare 年际：**只算增量与增/降率**，本步禁止归因 ⑤identify 峰值月份
    ⑥explain 季节与运行规律：**只允许挂两类依据**（见下「归因下沉三律」）
    ⑦identify 异常值 → 表注【待核实】。
  - 输出：数值段 + 图 + 增长率句 + 逐月特征句 + 异常表注 + 费用表 + 占比分析。
  - 触发：有该品种数据才写节；无逐月数据如实写"未获取完整逐月记录"。
- 5.3 指标（每项指标一节）：
  - 推理：①cite 标准定义（原文释义段）②公式 ③式中符号说明 ④calculate 三年值
    ⑤compare 定额约束/基准/引导 ⑥评价短语。
  - 输出：定义段 + 公式 + 式中 + 指标表（年耗量/系数/面积/人数/指标值/定额/评价
    七行键值表）+ 三年数值句 + 评价句。
  - 触发：定额数值未核验 → 评价列【待核验】，正文写"对照{标准}评价，数值待
    核验"，**禁止编造定额**；指标超标要解释原因（如人数少→人均分摊高）。
- 5.4 建筑能耗基准：
  - 推理：**⓪ 先论证基准期可比性**（六要素核对：报告期内新增建筑/区域投用、区域停用、
    围护结构或系统改造、主要用能设备更换、用能人数或业务量重大变化、计量统计口径变化；
    每条判定须能指到**数据来源**（审核可追溯）——**正文只写中文事实，英文字段名与反引号
    一律不进正文**，见 `energy-audit-core/references/report-format-spec.md`《正文禁忌》）→
    **可比**（或"可比但须说明"——仅命中节水器具更换等影响有限项，仍按三条规则取值、
    正文写明事实与影响范围）：cite（《核定办法》条文）→ 分品种 classify：逐年递增/递减 →
    取最近一年；±10% 内波动 → 取三年平均 → 汇基准表；
    **不可比**：机械取值不得作结论 —— 表内基准值加"（仅供参考，基准期待重定）"，
    正文写不可比事实＋证据＋建议基准期（改造前最后一个完整年度或单位确认的连续 12 个月）
    ＋"正式基准值待单位确认后重算【待核实】"；无从选择时直接【待核实】。
  - 输出：**可比性论证段（5.4 第一个自然段）** + 条文段 + 用量基准（分品种段+表）+
    费用基准（分品种段+表）。
  - 触发：必写；**先判可比性、再判波动性质**选基准期，禁止直接取平均；
    禁止套用《公共机构能源费用托管实施规程》的托管基准口径（那是能源托管项目专用，
    见本文《样板偏差记录》）。

**归因下沉三律（5.2 专用）**　2026-09-28 定。来源：淄博一四八医院样板 × 莘县中医医院
同节对照——样板 5.2 各节的年际段只有「增减量 + 增减率」，解释全部落在逐月段且只挂设备形式；
我方则在年际段就写「与业务量、管理措施有关」「节水管理成效逐步显现」，属越级归因。

1. **④ 年际对比步禁止归因** —— 本步只允许出现「增量 / 增减率 / 波动区间 / 极值」；
   出现「由于 / 因为 / 受…影响 / 与…有关 / 原因 / 导致」即判不合格。
2. **⑥ 归因只挂两类依据** —— ①设备与系统形式（冷源 / 热源 / 末端 / 循环泵，
   须能在 `buildings` 或 `equipment` 字段里指认）；②现场事件（新楼投用 / 区域停用 /
   改造工程，须有采集字段或用户书面确认）。**禁止挂「业务量 / 管理水平 / 节能意识」
   这类无计量支撑的泛因**；两类都挂不上时写「成因待核实」，不得写成原因句。
3. **同现象同向** —— 同一自然年、同一现象在 5.2 与 7.1 的定性必须同向：
   5.2 判「同比改善」，7.1 就不得把同年同现象写成「异常待核实」，反之亦然；
   冲突时以 7.1 的核验结论为准，回头修 5.2。

> **例外（2026-10-13 用户定）**：**平台登记的数据异常说明**（`data.json → energy_yearly[].anomalies`，
> 来源 `ts_institution_energy_main.anomaly_status` + `ts_institution_energy_exception`）写在
> 「**年际段之后另起的一段**」或「**逐月段之后另起的一行**」里，**不计入本律的禁归因范围**——
> 它是"异常说明"，不是对趋势的解释。落点、句式与只允许的两处修剪边界见
> `ea-calculation/references/chapter5-templates.md` 的 5.2 节。

#### 第6章 分系统分析

> **结构与编号的唯一权威**：`ea-authoring/references/chapter-guides-6-8.md`《第6章》
> （2026-10-21 重构）。本节只保留风格层要点，冲突时以指南为准。

- 主干：6.1 用电系统运行分析（（1）（2）…按实际系统动态生成）/ 6.2 用水 / 6.3 用热 /
  6.4 用燃气 / 6.5 其他用能 / 室内环境检测（按条件生成）。
- 每个用电系统固定三段：构成 → 运行方式 → 特点与评价；图随构成段、表随运行段。
- 只写事实与可验证评价，禁"建议/需/应/优化空间/浪费风险"（"改造"仅在"建议改造"等祈使语境禁用，已完成的节能改造可如实陈述）；

- 设备清单表 7 列：序号 / 设备名称 / 品牌 / 规格型号 / 数量 / 单台功率（kW）/ 运行时间；

#### 第7章 节能效果与潜力

> **结构权威**：`ea-authoring/references/chapter-guides-6-8.md`《第7章》（2026-10-21 重构）。
> 本节只保留风格层要点，冲突时以指南为准。

- 7.1 用能系统现状分析：7.1.1 能耗监测系统（固定第一节）+ 7.1.2… **一题一节的问题卡片**；
  不得用“数据异常/指标超标/用能系统及设备问题/计量与统计问题”等分类名作 7.1.x 标题。
- 7.1.1 按“用电 → 用水 → 用燃气 → 用热”判定，再写是否建设能耗监测系统（详见指南）。
- A/B/C 只作**内部证据规则**：A=实算数值、B=字段为真、C=设备台账/现场事实；不再作为章节结构。
- 问题卡片典型 3～8 节；顺序：计量 → 围护结构 → 空调与供暖 → 输配水泵 → 照明 →
  用水/灌溉 → 用燃气 → 生活热水 → 可再生能源 → 其他。
- 7.2 节能潜力分析及建议：7.2.1 建设能耗监测系统 + 与 7.1.2 起逐条对应；
  末尾固定“管理与行为节能”“节能率分析”两节。
- 依据锚点（沿用 2026-09-29 决策）：7.1.2 起 B/C 卡片“能引则引”一条——标准条文/定量数据/
  设备原理，融入句内；标题零条文；每条最多 1 部标准；查 `chapter7-anchor-table.md`。
- C 类开放方向仍为八项：控制方式、空调更新、照明更新、节水器具、充电桩/托管、可再生能源、
  水泵变频、峰谷电价；储能、电梯动能回收无字段时禁止写。
- 全章禁用“未登记/待平台补录/平台登记/系统数据”等平台语言。

#### 第8章 结论

- 结构（2026-09-29 用户决策，对齐三份外部样板）：**平铺式，不分节号、无表格**——
  ①方法段 ②定额引用段 ③指标逐条评价（编号 1.…2.…）④总体评价段（承"指标偏高原因"位置）
  ⑤建议清单（N 条，与 7.2 逐字一致）+ 预计效益 ⑥末段（后续工作建议合并为一段，可选）。
  标题为「第8章 审计结论」（不带"与建议"）；**废止** 8.1/8.2/8.3 分节与表8.1 指标对标汇总表。
- 建议清单的条数取 7.2.x 中除“节能率分析”以外的各节；每条建议独立成段，
  不得用分号堆在同一段。
- 推理：cite 审计方法句 → cite 定额标准 → compare 指标逐条评价（**复用第5章数值**）→
  总体评价（用能总量趋势 + 指标水平 + 超标原因，取第7章 7.1 原因表述）→ 汇总建议清单。
- 触发：必写；禁止引入前章没有的新数值；指标评价沿用第5章短语与【待核验】状态。

### 3. 机构类型差异（仅列与通用 8 章的差异，权威见 energy-audit-report 实例库）

| 差异点 | 法院/党政机关 | 医院 | 学校 |
|---|---|---|---|
| 定额标准 | DB37/T 2672-2019（机关，机构等级×气候区） | DB37/T 2673-2019（医疗，机构等级×气候区） | DB37/T 2671-2019（教育，**机构类型+二级分档，不分气候区**） |

## 句法模式 / 占位体系 / 禁词 / 评价短语（原 writing-style）

### 2. 占位体系（语义严格区分，禁止混用）

| 占位 | 语义 | 使用场景 |
|---|---|---|
| 【待补充】 | 数据缺失，可能后续人工补录 | 建筑参数、人员名单、设备清单、实测环境 |
| 【待核验】 | 标准数值未取得权威原文 | 定额约束/基准/引导值拿不到全文时 |
| 【待核实】 | 数据存疑，已提请单位确认 | 异常抄表值、费用-用量交叉不符 |
| 【以院方核定为准】 | 公开资料口径非官方数据 | 面积、床位等取自公开资料时，正文+表注 |

配套写法：

- 占位不影响段落完整性：句子结构完整，只把待定值换成占位符，**禁止整句删除**。
- 表内占位：整列填【待核验】等，保持表结构可读。
- 占位必须最终可回收：每个占位对应"谁来补、补什么"，无来源的占位=变相编造。

### 3. 禁词 / 禁用句式

| 禁用 | 原因 | 替代 |
|---|---|---|
| "我们可以发现""可能存在一定的问题" | 空泛、无数据支撑的主观句 | 数据+结论：`由表X.X可知，{现象}，表明{结论}` |
| "大幅""显著""严重"（无对照数据时） | 无量化依据的定性词 | 带数值：`超出幅度约{X%}` |
| "基本上""大概""左右"（正文指标句） | 报告指标句须精确 | 精确值；估算场景改用"约"并说明口径 |
| 编造姓名/电话/职称 | 事实造假 | 【待补充】 |
| 数值引前章 | 章节间口径漂移 | 一律从 data.json/indicators 读取 |
| "贵单位""本单位" | 正式报告用全称 | 单位全称 |
| 英式引号混排、半角标点 | 格式规范 | 全角中文标点 |

### 3b. 正文数值与括号规范（2026-10-15 用户定，全章适用）

**数值格式**（正文、表格、图注一律）：

| 情形 | 写法 | 反例 |
|---|---|---|
| 整数 | 不带小数位 | ~~17622.00 m³~~ → `17622 m³`；~~5090273.00 kWh~~ → `5090273 kWh` |
| 小数 | 保留两位 | `163107.70 m³`、`64.75 万元`、`29.65%` |
| 任何数值 | 禁千分位分隔符 | ~~1,762,200~~ → `1762200`（2026-10-09 已定，此处重申） |
| 数值与单位之间 | 空一格 | ~~57207m³~~ → `57207 m³`；~~5090273kWh~~ → `5090273 kWh` |

百分比同一条规则：整数不带小数位（平台登记 39.0% → `39%`），小数两位（`29.65%`、`8.47%`）。

**括号**：正文（叙述段）**禁止用括号承载统计数值、设备台数与运行参数**——括号在正文里
只用于三类：单位（全角，如 `kgce/（m²·a）`）、标准编号（如 `（DB37/T 2672-2019）`）、
图注里的"（单位：kWh）"。

| 禁用形态 | 反例 | 正例 |
|---|---|---|
| 月份后括号数值 | `用水量较大月份为2022年7月（17622m³）和8月（16724m³）` | `2022年7月和8月用水量分别为17622 m³、16724 m³` |
| 设备名后括号台数/参数 | `医院用气主要为燃气蒸汽锅炉（2台，供手术室区域，运行时间7:00-18:00）` | `医院用气主要为燃气蒸汽锅炉和厨房炊事设备，其中燃气蒸汽锅炉2台，供手术室区域使用，运行时间为7:00—18:00` |
| 设备名后括号品牌/功率 | `分体空调（格力，50台，1.06kW/台）` | `分体空调50台，单台功率1.06kW` |

> 依据：2026-10-15 用户判定这类写法"非常不规范"（岚山成品实测：5.2 段带数字括号 9 处，
> 用气/用水/第6章各有一套形态）。机械检查 `ea_docx_asserts.py::ch5_num_style`（P1 只告警）。

### 3c. 占位标记的红色渲染（2026-10-16 用户定）

正文里含**占位标记**的**句子**一律渲染成红字（`C00000`，与 5.2.1 红注同色）：

- 触发词：`【待核实】`/`【待补充】`/`【待核验】`/`【待确认】`，以及**不带括号的裸写法** "待核实"
  （实测 5.2.4、5.4.2、第6章 都在用裸写法，只盯括号形式会漏一半）；
- 粒度＝**句子**（按 `。；` 切分，分隔符随前句）：同一段里其他句子保持黑色，**整段不染**；
- 落点＝装配器 `build_energy_audit_docx.py::_body`（`VERIFY_MARK_RE` + `_split_by_verify`），
  所有章节正文段落自动生效，无需在 md 里写标记。

### 4. 评价短语（固定词表，纯短语无括号后缀）

- 高于约束值 / 低于约束值
- 高于基准值 / 低于基准值
- 高于引导值 / 低于引导值

## 防抄三闸门与查重（原 anti-copy-gate）

仿写参考报告时，三道闸门按序通过才算合格。第 1 闸在提示词层（生成时约束），
第 2 闸在提示词层+审查层，第 3 闸是生成后的机械查重（脚本）。

### 第 1 闸：事实层（禁抄事实）

- 禁抄参考报告的单位名称、人名、人数、面积、能耗数值、费用、年份、设备参数。
- 生成文中的所有事实必须来自本项目数据（data.json / indicators / DB 采集）。
- 判定：生成文中出现参考报告专有名词/数值 → 事实层违规，直接重写。

### 第 2 闸：句法层（禁整句复述）

- 学的是修辞结构（段落组织、表格习惯、结论句要素），不是句子本身。
- **禁止与参考报告出现连续相同文字**。红线：
  - 连续 12 字及以上与任一参考段落完全相同 → 违规；
  - 连续 8~11 字相同出现 2 处及以上 → 违规；
  - 整句同构（仅替换单位名/数值，语序与虚词完全一致）→ 违规，须重组句式。
- 例外（不算违规）：固定条款原文（法律/标准引用、4.1 计量体系六条、附录
  固定表格如空气质量判定 A-D 表）、指标定义段的标准原文释义。
- 判定：生成时提示词必须明示"改写句式，禁止整句复述"；审查时人工/脚本比对。

### 第 3 闸：查重层（生成后机械查重）

工具：`tools/energy_audit/similarity_gate.py`（仿写链路自动调用），
`energy-audit-style/scripts/similarity_check.py`（editor 手动检查任意两份文本）。

算法：中文 n-gram（n=6）集合相似度 + 最长公共子串（LCS）双重指标：

- `lcs_ratio` = 最长公共子串长度 / 生成文本长度；
- `ngram_overlap` = 生成文本 6-gram 与参考文本 6-gram 的交集占比；
- 任一指标超阈值即报"疑似复述"。

默认阈值（`tools/energy_audit/similarity_gate.py` 常量，可调）：

| 指标 | 阈值 | 含义 |
|---|---|---|
| lcs_ratio | ≥ 0.15 | 与参考报告存在长段连续相同文字 |
| ngram_overlap | ≥ 0.25 | 短语级高度雷同（同构改写也逃不掉） |

处置：

- 仿写链路：违规段落标记 `similarity_flags` 返回给调用方（editor 终审必看），
  不静默丢弃。
- editor 终审：任一章节违规 → 该章重写（换句式，事实仍用本项目数据），重写
  后再查，直至通过或人工判定为例外条款。
- 例外条款白名单：1.6 依据清单、4.1 六条固定文字、5.3 定义段原文释义、附录
  固定表格——命中白名单前先确认段落确实属于白名单类别。

### 白名单（本来就该逐字相同的内容，2026-09-20 定）

**为什么需要**：正式报告里有一批内容**本来就应当逐字相同**——章节标题、表格骨架与字段名、
标准定义原文、审计依据清单、计量体系固定条文、指标定义段、附录固定表格。
不排除它们，任意两份同类报告都会出现 **LCS 65~70%** 的"合法重合"（2026-09-20 A/B 实测），
真问题被淹没、editor 会逐渐忽略查重结论。

| 类别（脚本键名） | 判定要点 | 例 |
|---|---|---|
| `heading` 标题行 | 整块以 `#` 开头 | `## 1.3 审计周期` |
| `table` 表格行（骨架/字段名） | 整块以 `|` 开头 | `\| 项目 \| 内容 \|` |
| `definition` 审计定义段 | 含"公共机构能源审计是指……" | 1.1 第 1 段 |
| `standards_list` 依据清单行 | 行首为 `-`/`·`/`⚫` 且含标准编号（GB/DB37/JGJ/CJJ/JS/T/鲁事管发/国管局令） | 1.6 各条 |
| `metering_clause` 计量固定条文 | 含"分户计量/分区计量"且长度 < 400 字 | 4.1 GB/T 29149 六条 |
| `indicator_definition` 指标定义段 | 含"在统计报告期内"或"计算公式如下"+"单位为" | 5.3 各指标释义 |
| `appendix_fixed` 附录固定说明/表 | 含"空气质量判定/折标准煤参考系数/室内空气质量指标及要求" | 附录 5/6/7 |

**使用方式**：

- 默认**启用**白名单（脚本 `tools/energy_audit/similarity_gate.py::filter_whitelist`，CLI `similarity_check.py`）；
- 结论行会打印"已豁免白名单 N 块：表格行 x、审计依据清单行 y…"——**这些豁免仍需人工扫一眼是否合理**（防止把该查的内容误判成白名单）；
- 排查问题时用 `--strict` 关闭白名单，看裸文本比率；
- 白名单类别只能通过修订本节来增删（脚本常量 `WHITELIST_LABELS` 与本节须同步）。

### 变量一致性闸门（与查重并列的第二道，2026-09-20 定）

**判据修正**：报告类文档里，**文字相同不是缺陷**——固定条款/标准原文/审计程序叙述/结构骨架/
术语/评价短语本来就该逐字一致（2026-09-20 实测：同类报告间这些段落必然 65~70% 重合）。
真正要管的是：**该随项目变的那些变量，是否真的变了**。

| 类别 | 相同意味着 | 谁管 |
|---|---|---|
| 固定条款 / 标准原文 / 审计程序 / 结构骨架 / 术语 | ✅ 正常（合规惯例） | 不查（白名单声明） |
| 项目变量：数值 / 单位名 / 地址 / 人员 / 设备名 / 机构名 / 年份 / 定额取值 | ❌ 必须来自**本项目**数据源 | **变量一致性闸门** |

**工具**：`python <skills>/ea-validation/scripts/verify_variables_provenance.py <项目名> [--blueprint <蓝本md> ...]`

- 先过白名单剔除固定条款，再抽变量（数值/机构名/年份），逐个回查本项目数据源
  （`data.json` / `indicators.json` / `chapter5.md`）；
- **P0**：变量出现在蓝本、却不在本项目数据源 → 蓝本变量泄漏（真问题，退出码 1）；
- **P1**：既不在数据源也不在蓝本 → 待确认（可能为派生值如百分比/均值，或来源缺失）；
- 相似度查重（第 3 闸）降级为**参考信息**，不再单独作为交付判据。

**两道闸的分工**：查重 = "有没有整句照搬别人的变量"；变量闸门 = "该变的是否真变"。两者都跑才算合格。

- [ ] 生成稿与参考报告的专名/数值零重合（事实层）。
- [ ] 无连续 12 字以上照搬；同构句已重组（句法层）。
- [ ] 查重脚本已跑，lcs_ratio < 0.15 且 ngram_overlap < 0.25（查重层）。
- [ ] 白名单例外均有据（确属固定条款/标准原文）。
- [ ] 违规章节已重写并复查通过。
