### 第6章总指南

#### 1. 章标题与主干

**第6章 主要能源资源利用系统分析**

```

```

- 6.1 下用（1）（2）（3）编号；系统名不进目录；正文引用写"6.1 中的照明系统"。
- 6.1 开头必须有总述句，点到的系统与后续小节一一对应。

- 室内环境节的结构与详略待 D15 决议；未定前不得改动既有形态。

#### 2. 6.1 用电系统运行分析

##### 2.1 动态系统与顺序

固定顺序：**空调与供暖 → 照明 → 办公设备 → 其他用电设备 → 特殊用能系统（信息机房与医疗设备合并）→ 变配电**。
没有的系统跳过，编号顺延。

| equipment.category / 设备 | 归入小节 |
|---|---|
| 空调、输配（冷冻/冷却水泵）、其他设备中的冷却塔 | （n）空调与供暖系统 |
| 照明 | （n）照明系统 |
| 办公 | （n）办公设备 |
| 动力（电梯、电开水器、生活水泵等） | （n）其他用电设备 |
| 特殊设备（信息机房）、医疗设备 | （n）特殊用能系统 |
| 变配电、变压器 | （n）变配电系统 |

##### 2.2 每个系统固定三段

1. **系统构成**：设备名称、数量、单台功率、服务范围；
2. **运行方式**：季节、时段、控制方式（有字段才写，缺失不写具体时段）；
3. **运行特点与评价**：实算数据，或"未单独计量，无法单独核算"。

图贴构成段后，表贴运行段后。章末不另设"运行评价"节。

##### 2.3 设备清单表（每系统一张）

列固定：

`序号 | 设备名称 | 品牌 | 规格型号 | 数量 | 单台功率（kW） | 运行时间`

- `equipment.spec` 按 `|` 拆分：含 kW/W → 单台功率（W 换算 kW）；`运行:` → 运行时间；
  **纯数字片段绝不进规格型号**；无品牌/型号写"—"。
- 数量取 `equipment.quantity`；为 0 写"—"。
- **合并键 = 设备名称 + 品牌 + 规格型号 + 单台功率 + 运行时间**；同名同键合并、数量相加；
  合并后按单台功率降序排列。
- 表题：`表6.X XX系统设备清单`，不带单位名；表号在章内连续。

##### 2.4 照片

- 每个合并后的设备表行插 1 张照片（同一条目多张时取 `img_ids` 数据顺序第一张）；
- 图注：`图6.X 设备名`，不带单位名；图号按实际插图顺序连续；
- 有 `img_ids` 却未插图 → V3 告警；确实没有照片不阻断。

#### 3. 6.2 用水系统运行分析

##### 3.1 段1 用水构成

固定开头：

> {单位简称}用水主要为生活用水（主要为清洗用水、卫生间用水等）[、灌溉用水][及空调供暖系统补水]。

- **灌溉用水**：`ts_institution_water_greening`（`data.json → water_aux.greening`）有有效内容才写；
  收资确认没有则不写。
- **空调供暖系统补水**：`ts_institution_device_other` 有"空调系统补水装置"才写：
  - 冷源为冷水机组、热源为市政供暖 → "空调供暖系统补水"；
  - 只有冷水机组 → "空调系统补水"；
  - 只有市政供暖 → "供暖系统补水"。
- 若冷热源只登记一项、怀疑漏填，先在收资阶段确认；确认没有的项不写。

##### 3.2 段2 生活给水方式

按 `ts_institution_device_power` 中"生活水泵"的 `config`（配置情况）判断：

| 配置情况 | 固定句式 |
|---|---|
| 生活水箱 + 无负压都有 | 生活给水系统分别采用市政自来水经生活水箱储存、生活水泵加压和无负压供水两种方式。 |
| 只有生活水箱 | 生活给水系统采用市政自来水经生活水箱储存、生活水泵加压的供水方式。 |
| 只有无负压 | 生活给水系统采用市政自来水无负压供水方式。 |
| 没有生活水泵 | 生活给水系统采用市政自来水直供方式。 |

⛔ 禁止"生活水箱+生活水泵加压方式"这类工程简写，禁止"+"号。

##### 3.3 段3 固定句

> 消防系统用水量较少，忽略不计。

##### 3.4 6.2 设备表

有生活水泵、补水装置等给排水设备时，附一张 `表6.X 给排水系统设备清单`，列仍按 2.3 的 7 列。

#### 4. 6.3 用热系统运行分析

##### 4.1 段1 热源与供暖方式

- 单一热源：`{单位简称}供暖采用{热源}，供暖末端为{末端}，采暖期为{起}至{止}。`
- 多栋建筑热源不同：按建筑分组写。
- 末端有多种：写"以{主末端}为主，部分区域采用{次末端}"；"精密空调室内机"统一写"空调室内机"。

##### 4.2 段2 计量与结算

- 按面积：`供暖按建筑面积计缴热费，供暖面积{面积} m²，热价为{单价}元/m²，未安装热量计量表，供热量无法单独计量。`
- 按热量：`供暖按热量计缴热费，安装热量表，热价为{单价}元/GJ。`
- 缺失项不编；影响结论时用红字【待核实】。

##### 4.3 段3 热耗特点

- 有供热量：写三年供热量与趋势；
- 只有热费：写三年供暖费用与趋势；
- 两者都没有：`供热量及供暖费用数据需进一步核实【待核实】，暂无法分析逐年热耗。`

#### 5. 6.4 用燃气系统运行分析

##### 5.1 段1 气源与用气设备

- 写气源（管道天然气/液化石油气）与已获取信息的用气设备；
- 只写已获取信息的设备，不臆造食堂用气；
- 有服务区域的要写（如"布置于手术室区域，为消毒用蒸汽提供热源"）。

##### 5.2 段2 用气环节与运行

- 蒸汽锅炉：台数、服务区域、运行时间；
- 炊事：供餐时段、灶具数量（有登记才写）；
- 运行时间缺失不写具体时段。

##### 5.3 段3 用气特点与计量

- 三年用气量 + 趋势：单调上升/下降写"呈逐年上升/下降态势"，非单调按 5%/10%/15% 四档；
- 有气费补气费；
- 已登记设备之外仍有明显用气用途时，写"其他用气设备情况需进一步核实【待核实】"，收资确认后删除。

#### 6. 6.5 其他用能系统运行分析

- 有汽油/柴油实物量、车辆数量 → 写具体数量与趋势；
- 只有费用 → 只写费用与趋势，**不写**"实物量/车辆数量未取得"这类缺口句；
- 无任何其他用能 → 不生成该节。

#### 7. 通用写作规则

1. 第6章只写事实与可验证评价；禁"建议/需/应/优化空间/浪费风险"等建议性措辞。
   "改造"仅在"建议改造/应改造/需改造"等祈使语境禁用；已完成的节能改造（如"2023年统一改造更换"）可如实陈述。
2. 无分项计量不得推断占比；无光效数据不得评价光效；无量化依据不得说"导致指标偏差"。
3. 表格缺值写"—"；正文缺失按"不写 / 红字【待核实】/ 事实说明"三级处理。
4. **全报告禁用**"未登记""待平台补录""平台登记""系统数据"等内部管理/平台语言；
   改用"现场未获取到""资料未提供""需进一步核实"。
5. 第6章**不引用第5章图表**，需要数据时直接写实算数值；第7章只引系统名，不引"6.1（2）"编号。
6. 数值：整数不带小数位，非整数保留两位，禁千分位；数值与单位之间空一格。

#### 8. 校验（V3）

1. 章标题必须为"第6章 主要能源资源利用系统分析"；
2. 6.1/6.2 必备；6.3/6.4/6.5/室内环境按条件生成；
3. 6.1 至少 3 个（n）小节，且与总述句一致；
4. 每个系统小节至少 3 段有效正文；
5. 设备表 7 列表头、表号连续；图注数=图片数、编号连续，有 `img_ids` 未用告警；
6. 禁词检查（含平台语言、建议类词）；
7. 第6章不得出现"详见第5章图…"类引用。

## 第7章 节能效果与节能潜力分析（2026-10-21 重构，样板口径）

> **结构权威**：以本章为准。旧 R7 的“7.1 平铺（1）（2）… A/B/C 混排”结构自 2026-10-21 起废止。
> A/B/C 只保留为**内部证据规则**，不再作为 7.1 的章节名或编号方式。

### 一、章节结构

```
第7章 节能效果与节能潜力分析

7.1 用能系统现状分析
    7.1.1 能耗监测系统（固定第一节）
    7.1.2 …（具体问题卡片，一题一节）
    7.1.3 …

7.2 节能潜力分析及建议

    7.2.2 …（与 7.1.2 起逐条对应）
    7.2.N 管理与行为节能（固定倒数第二节）
    7.2.N+1 节能率分析（固定末节）
```

- 7.1.x **一题一节**：标题就是“问题名”，如“照明灯具能效低、智能化程度低”“建筑围护结构保温效果差”“空调与供暖系统缺少智能控制”。
- 典型 3～7 节；按项目实际问题取，不凑数。
- ⛔ 禁止把“数据异常/指标超标/用能系统及设备问题/计量与统计问题”这类**分类名**当 7.1.x 标题。
- 7.1.1 固定为计量/监测，不得后移；其余卡片顺序：围护结构 → 空调与供暖 → 输配水泵 → 照明 → 用水/灌溉 → 用燃气 → 生活热水 → 可再生能源 → 其他（电梯、峰谷电价等）。

### 二、7.1.1 能耗监测系统（固定判定树）

先按“用电 → 用水 → 用燃气 → 用热”四类描述计量现状，再判断是否建设能耗监测系统。

#### 2.1 用电

数据：`metering.electric_meters`、`independent_aircon / independent_light_socket / independent_power / independent_special`、
`equipment[].independent_metering`（主要用能设备独立计量“有/无”）、`metering.ledger_text`（电表台账）。

> 分项计量状态按年份留档于 `metering.electric_metering_by_year`（`sub_metering` / `scenario`）。
> 取**审计期最后一年**的状态；不同年份记录冲突时写【待核实】，不得静默二选一。

主要用能设备范围：冷热源设备、供暖空调输配设备、医疗设备、生活水泵、单独照明、信息机房、厨房设备。

| 分支 | 条件 | 固定表述 |
|---|---|---|
| E1 | 仅总计量电表 | 本项目用电计量仅安装总计量电表，仅能对项目内总用电量进行计量。 |
| E2 | 有楼栋/区域电表，但未按四大分项计量 | 本项目用电除总表外，按楼栋/区域设置了计量电表，但未按空调、照明插座、动力、特殊用电四大分项计量，也未对主要用能设备独立计量，计量颗粒度较粗。 |
| E3 | 有四大分项，但无主要设备计量 | 本项目用电能够实现空调、照明插座、动力系统用电计量，但未对{特殊设备清单}等特殊设备独立计量，未对主要用能设备单独计量。 |
| E4 | 有四大分项，主要设备计量＜50% | 本项目用电能够实现空调、照明插座、动力系统用电计量，同时部分主要用电设备（列 2 项，只有 1 项列 1 项）已实现独立计量，但未实现所有主要设备独立计量。 |
| E5 | 有四大分项，主要设备计量 50%～70% | 本项目用电能够实现四大分项计量，部分主要用能设备已独立计量，但主要设备计量覆盖率仍不足，尚未实现主要用能设备全面独立计量。 |
| E6 | 有四大分项，主要设备计量＞70%，未建能耗监测系统 | 本项目用电能够实现四大分项计量，大部分主要用能设备（列 2 项）已实现独立计量；但日常用电数据仍采用人工管理方式，无法实时开展数据对标、异常排查和异常预警。 |
| E7 | 有四大分项，主要设备计量＞70%，已建能耗监测系统 | 本项目用电已实现四大分项计量及大部分主要用能设备独立计量，并建设能耗监测系统，具备较好的分项统计基础。 |

> 覆盖率 = 已独立计量的主要用能设备类别数 ÷ 本项目实际存在的主要用能设备类别数。
> 分母只算本项目实际存在的类别；设备数量为 0 或未登记的不计入分母。

#### 2.2 用水

数据：

- `energy_meter`（`data_type=2` 水表）：`meter_count`、`measured_depth`（仅总表/楼栋/楼层/科室…）、
  `kitchen_water`（厨房用水单独计量 0/1）、`year_water_value`；
- `water_aux.greening[].is_metering`（灌溉是否单独计量）；
- `water_aux.other[].water_system` + `is_metering`（空调/供暖补水等其他特殊用水系统是否单独计量）；
- `water_aux.road`（道路冲洗，无单独计量字段时只写事实）。

| 分支 | 条件 | 固定表述 |
|---|---|---|
| W1 | 仅总表 | 本项目用水计量仅安装总计量水表，仅能对项目内总用水量进行计量。 |
| W2 | 总表＋＜80% 楼栋有表；无楼层/科室；有厨房/空调供暖/灌溉但未单独计量 | 本项目用水计量除总表外，部分楼栋已安装水表，能够实现部分楼栋用水计量，但无法覆盖所有建筑；未对厨房用水、供暖空调用水、灌溉用水进行分类计量。单栋建筑时省略“部分楼栋”句。 |
| W3 | 总表＋＞80% 楼栋有表；无楼层/科室；上述用途未单独计量 | 本项目用水计量除总表外，能够实现各楼栋用水单独计量，但未实现建筑各功能区用水独立计量；未对厨房用水、供暖空调用水、灌溉用水进行分类计量。 |

| W6 | 总表＋＞80% 楼栋有表；已实现楼层/科室；上述用途已单独计量 | 本项目用水计量除总表外，能够实现各楼栋及建筑内各功能区用水单独计量；已对厨房用水、供暖空调用水、灌溉用水进行分类计量。 |

#### 2.3 用燃气

用两张表判断燃气用途：

- **厨房炊事用气**：`ts_institution_device_special` 中厨房/食堂相关行 `has_gas_use=1`；
  该行 `is_metering` 判断厨房炊事用气是否单独计量（1=有，0=无，空=未登记）。
- **供冷供热用气**：`ts_institution_device_air` 中 `gas_value>0`，或设备名称含“燃气/溴化锂/锅炉”；
  该行 `is_metering` 判断供冷供热用气是否单独计量。

判断：

- 两者都存在，且任一 `is_metering=0` → “本项目供冷供热用燃气与厨房炊事用燃气未实现分别独立计量。”
- 只有一项存在 → 只写该项设备与计量情况（如“燃气蒸汽锅炉未单独计量”）。
- 两项均无有效记录、但燃气表有消费 → “厨房炊事及供冷供热用气设备情况待进一步核实【待核实】”，
  不得断言“未分别计量”或“无此用途”。
- 蒸汽锅炉仅用于消毒/工艺时，单列在燃气设备中，不计入“供冷供热用气”。

#### 2.4 用热

- `heat_meters=0` 或 `heat_pay_type=按面积缴费` → “本项目供暖按面积缴费，未安装热量计量表，供热量无法单独计量。”
- 有热量表 → 写“已安装热量表，按热量计量/结算”。

#### 2.5 能耗监测系统

- `has_monitoring_system=false` → “本项目未建设能耗监测系统，日常能源数据主要依靠人工抄录，难以实时开展数据对标、异常排查和异常预警。”
- `true` → 如实写已建系统及覆盖范围。

### 三、7.1.2 起：问题卡片库

每张卡片 = 触发条件 + 必写事实 + 可选锚点 + 对应 7.2 建议。**没有触发条件的卡片不生成。**

| 卡片 | 触发条件 | 必写事实 | 对应 7.2 |
|---|---|---|---|
| 建筑围护结构 | 外窗为单层/普通玻璃，或外墙/屋面保温缺失 | 建筑名、外窗/墙体/屋面现状、影响 | 围护结构改造 |
| 空调与供暖控制 | `metering.cold_control_type` 为人工/半自动，或无集中控制 | 控制方式、设备启停方式、影响 | 空调智慧管控改造 |
| 输配水泵变频 | `equipment` 输配设备存在“定频” | 水泵台数、功率、定频事实 | 水泵变频改造 |
| 照明系统 | 存在普通荧光灯/高耗灯具，或无节能控制 | 灯具类型、数量、控制方式 | 照明系统改造 |
| 用水/灌溉 | 灌溉方式为漫灌/浇灌，或节水器具未更换 | 灌溉方式、用水环节、器具现状 | 节水/灌溉改造 |
| 用燃气 | 燃气设备未单独计量，或存在明显用气管理缺口 | 设备、用途、计量状态 | 燃气计量/管理 |
| 生活热水 | 电热水器/热泵系统能效低或控制粗放 | 设备、数量、运行方式 | 生活热水改造 |
| 可再生能源 | `solar.has_solar_utilization=0` 且有可安装条件 | 现状、可安装条件（屋面/车棚） | 光伏/太阳能建设 |
| 电梯 | 有电梯台账且未配动能回收 | 电梯数量、配置 | 电梯节能改造 |
| 峰谷电价 | `metering.electric_pay_type=分时电价` | 电价方式、可转移负荷 | 错峰用电 |
| 充电桩/托管 | `charging_pile=0` / `third_party_outsource=0` | 现状事实 | 充电桩/托管 |

> C 类未开放方向（储能、电梯动能回收无字段时）仍禁止写；电梯卡片仅在已有电梯台账时启用。

### 四、A/B/C 的内部用法

- C（机会）：设备台账/现场事实。
