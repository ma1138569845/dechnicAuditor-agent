### 第6章总指南

#### 1. 章标题与主干

**第6章 主要能源资源利用系统分析**

```
第6章 主要能源资源利用系统分析

6.1 用电系统运行分析（必备）
    （1）…（n）按实际用电系统动态生成
6.2 用水系统运行分析（必备）
6.3 用热系统运行分析（有供暖/热源才生成）
6.4 用燃气系统运行分析（有燃气使用才生成）
6.5 其他用能系统运行分析（有车辆燃油等才生成）
6.x 室内环境检测（有检测数据才生成）
```

- 6.1 下用（1）（2）（3）编号；系统名不进目录；正文引用写"6.1 中的照明系统"。
- 6.1 开头必须有总述句，点到的系统与后续小节一一对应。
- 无燃气、无供暖、无其他用能时，对应节不生成，后续编号顺延。
- 室内环境节的结构与详略待 D15 决议；未定前不得改动既有形态。

#### 2. 6.1 用电系统运行分析

##### 2.1 动态系统与顺序

固定顺序：**空调与供暖 → 照明 → 办公设备 → 信息机房 → 医疗设备 → 变配电 → 其他用电设备**。
没有的系统跳过，编号顺延；“其他用电设备”固定最后。

| equipment.category / 设备 | 归入小节 |
|---|---|
| 空调、输配（冷冻/冷却水泵）、其他设备中的冷却塔 | （n）空调与供暖系统 |
| 照明 | （n）照明系统 |
| 办公 | （n）办公设备 |
| 特殊设备中的数据服务器、网络、存储等，数据库每一行总功率 **>100 kW** | （n）信息机房系统 |
| 特殊设备中的医疗设备，且本单位为二级或三级医院 | （n）医疗设备系统 |
| 变配电、变压器 | （n）变配电系统 |
| 动力（电梯、电开水器、生活水泵等）及其他零散用电设备 | （n）其他用电设备（固定最后） |

路由结果的权威来源是 `tools/energy_audit/project_data.py` 的 `chapter6_route_for_equipment()`：写作和审查都必须按项目 `base` 的当前规则重算。`equipment_section_key / photo_section_key` 只是缓存结果；旧快照没有按当前规则重算时，不得直接作为写作或审查依据。

- 数据中心/信息中心按数据库每一行独立判断，不得在缺少明确分组字段时把多行功率相加；该行总功率 **≤100 kW**，或缺少明确 `power_unit` 导致总功率无法确认时，归“其他用电设备”；后者须在数据核查中补单位，报告不得猜算；
- 特殊设备功率明细必须有明确 `power_unit` 才能换算 `total_power_kw`；没有单位时保留“数量×单机功率”的原始明细，但不得据此判断是否超过 100 kW；
- 医疗机构以 `unit_func=C` 为权威；只有平台码为空时才按机构类别或单位名回退。二级、三级医院分别对应 `children_func=B/C`，并兼容“二级”“三级”中文值；一级医院或非医疗机构中的“医疗设备”归“其他用电设备”；
- 只有冷却塔、空调系统补水装置、末端设备可归“空调与供暖系统”；阀门等普通“其他设备”默认归“其他用电设备”；
- `ts_institution_device_hygiene` 的卫生器具（含坐便器、蹲便器、水龙头等）设备和照片统一归 6.2 用水系统；
- 生活水泵的设备事实和照片均归“其他用电设备”，不得放入 6.2 用水系统；`ts_institution_device_hotwater` 中“生活热水”分类的全部设备，其设备事实按能源形式归属：燃烧型设备写 6.4 用燃气系统，非燃烧型设备写 6.1 其他用电设备；无论事实写在哪一节，只要该设备上传了照片，照片统一且仅放一次到 6.2 用水系统；燃气/燃油锅炉等非生活热水表设备的事实与照片归 6.4；“吸收式/溴化锂/直燃”设备只有台账 `gas_value` 或 `fuel_value` 大于 0 才按燃烧型处理，0 或空值不触发燃烧路由；
- 末端设备来自 `ts_institution_device_terminal`，当前该表无图片字段，不强制配图，但正文和设备表必须保留；
- 变配电设备、表格和正文按数据保留；当前平台变配电主/附表无图片字段，不强制配图。

##### 2.2 每个系统固定三段

1. **系统构成**：设备类别/成套系统、总数量、总装机容量（有则写）、服务范围；
   只做系统级概述，不逐项罗列品牌、型号和单台功率；
2. **运行方式**：季节、时段、控制方式（有字段才写，缺失不写具体时段）；
3. **运行特点与评价**：实算数据，或"未单独计量，无法单独核算"。

图贴构成段后，表贴运行段后。章末不另设"运行评价"节。

**设备明细下沉（强制）**：品牌、型号、每类数量、单台功率和运行时间以设备清单表
为唯一完整载体；正文不得把表格逐行改写成汉语句子。同一段出现 3 组及以上
「数量＋单台功率」明细，或 2 个及以上具体型号时，即判设备明细未下沉（V3 P1）。
只有具体型号本身构成能效评价、淘汰落后或改造判断依据时，才可在评价段点出该型号，
且不重复其余设备行。

##### 2.3 设备清单表（每系统一张）

列固定：

`序号 | 设备名称 | 品牌 | 规格型号 | 数量 | 单台功率（kW） | 运行时间`

变配电系统使用专用表：

`序号 | 设备名称 | 规格型号 | 形式 | 数量 | 单台容量（kVA） | 安装时间`

变压器专表保留容量、形式和安装时间，不强行套用“品牌/单台功率/运行时间”。

- `equipment.spec` 按 `|` 拆分：含 kW/W → 单台功率（W 换算 kW）；`运行:` → 运行时间；
  **纯数字片段绝不进规格型号**；无品牌/型号写"—"。
- 数量取 `equipment.quantity`；为 0 写"—"。
- **合并键 = 设备名称 + 品牌 + 规格型号 + 单台功率 + 运行时间**；同名同键合并、数量相加；
  合并后按单台功率降序排列。
- 表题：`表6.X XX系统设备清单`，不带单位名；表号在章内连续。

##### 2.4 照片

- **写章前先看事实目录**：运行
  `prepare_report_photos.py <项目名> --catalog-only --vision`，读取
  `chapter_md/_context.md` 的“照片事实目录”。只有候选的 `核验状态=pass` 时，
  才能在正文或图注中写图片内可见的品牌、型号、设备外观特征；状态为
  `review`/`unverified` 时只能使用设备台账绑定和中性图注。
- 事实目录和 `chapter_md/_context.md` 必须明确显示每张设备照片的目标小节（例如 `6.2 用水系统`、`6.4 用燃气系统`）；作者按下表落位，不得把所有设备照片混放回 6.1。
- 同一物理照片只进入一个更具体的小节：生活水泵照片放在 6.1“其他用电设备”，燃气设备照片优先 6.4，不得跨小节重复。
- `equipment[].img_fields[].ids[]` 中每个非空附件 ID 都必须形成独立图片槽位；同一字段有多个附件时逐张展开口径见 2.5；
- 图注命名：设备只有一个非空附件槽位时写 `图6.X 设备名`；同一设备有多个非空附件槽位时，逐张写 `图6.X 设备名+字段名称`（正文不出现“+”号）。例如 `图6.1 冷冻水泵设备整体图片`、`图6.2 冷冻水泵电机铭牌图片`。图注不带单位名，图号按实际插图顺序连续；
- 多字段设备的每条图注必须精确匹配到字段名称，不能用一条短设备名图注代替多张字段照片；
- “其他设备”不得把数据库里的泛化选项名当标题。按来源表回显真实名称：
  - 冷热源、末端、照明、特殊设备：泛化选项在 `device_name`，真实名称取 `other_device_name`；
  - 办公设备：泛化选项在 `type`，真实名称直接用 `device_name`；
  - 普通明确设备名不得被同表的其他名称字段覆盖；真实名称缺失时保留原泛化名，交数据核查处理，禁止猜填；
- 排版：图片宽度统一 **6.8cm**、等比缩放、**每行两张**；图注分别置于对应图片下方，
  最后只剩一张时单独居中。只对第6章设备照片生效，其他章节图片尺寸不变；
- 归置器同时校验图注所在的 `6.x` 小节；照片放错系统小节时告警“当前放在 X，应在 Y”，但不阻断报告装配；
- `prepare_report_photos.py` 在发现“附件 ID 没有对应图注”时返回 rc=2；
  V3 报 `V3.STRUCT.CHAPTER6_PHOTO_COVERAGE`（P1）。确实没有图片字段才不阻断。

##### 2.5 设备照片逐附件规则

- `equipment[].img_fields[]` 中每个非空附件 ID 都必须在报告中形成一个独立图片槽位。
- 同一字段有多个附件时，逐张写连续图注；图注文字可以使用设备名或“设备名+字段名”，图片编号必须连续且唯一。
- 动力设备表、特殊设备表只要有附件 ID，就必须从数据库反向检查报告是否逐槽位配图，不能以 Markdown 设备表是否列写该设备作为免检条件。
- 附件已登记但本地文件缺失时，写技术告警并继续装配；由现有“暂缺”图示和审查告警暴露，不阻断 Word 生成。
- 普通“电梯机房、消防机房、水泵机房、空调机房”不得识别为信息机房。只认“数据中心、信息中心、信息机房、数据机房、服务器、网络设备、存储设备”等明确证据。
- 数据中心/信息中心按数据库每一行作为独立系统判断；总功率大于 100 kW 才单列，等于 100 kW 或无法确认时并入“其他用电设备”。没有明确分组字段时不得把多行功率相加。
- 医疗机构以 `unit_func=C` 为权威；只有平台码为空时才按机构类别或单位名回退。二级、三级分别对应 `children_func=B/C`，并兼容“二级”“三级”中文值。

#### 3. 6.2 用水系统运行分析

##### 3.1 段1 用水构成

固定开头：

> {单位简称}用水主要为生活用水（主要为清洗用水、卫生间用水等）[、灌溉用水][及空调供暖系统补水]。

- **灌溉用水**：`ts_institution_water_greening`（`data.json → water_aux.greening`）有有效内容才写；
  收资确认没有则不写。
- **空调供暖系统补水**：`ts_institution_device_other` 有"空调系统补水装置"才写：
  - 冷源为冷水机组、热源为市政供暖 → "空调供暖系统补水"；
  - 只有冷水机组 → "空调系统补水"；
  - 只有市政供暖 → "供暖系统补水"。
- 若冷热源只登记一项、怀疑漏填，先在收资阶段确认；确认没有的项不写。

##### 3.2 段2 生活给水方式

按 `ts_institution_device_power` 中"生活水泵"的 `config`（配置情况）判断：

| 配置情况 | 固定句式 |
|---|---|
| 生活水箱 + 无负压都有 | 生活给水系统分别采用市政自来水经生活水箱储存、生活水泵加压和无负压供水两种方式。 |
| 只有生活水箱 | 生活给水系统采用市政自来水经生活水箱储存、生活水泵加压的供水方式。 |
| 只有无负压 | 生活给水系统采用市政自来水无负压供水方式。 |
| 没有生活水泵 | 生活给水系统采用市政自来水直供方式。 |

⛔ 禁止"生活水箱+生活水泵加压方式"这类工程简写，禁止"+"号。

##### 3.3 段3 固定句

> 消防系统用水量较少，忽略不计。

##### 3.4 6.2 设备表

有卫生器具、生活水泵、补水装置等给排水设备时，附一张 `表6.X 给排水系统设备清单`，列仍按 2.3 的 7 列。

卫生器具、绿化灌溉、其他用水设施以及生活热水系统表全部设备的照片按 `photo_section_key=water_system` 放在 6.2，生活热水设备照片不得在 6.4 重复。生活水泵照片必须跟随设备事实放在 6.1“其他用电设备”，不得进入 6.2。照片来源为 `equipment[].img_fields[]` 或 `water_aux.*[].img_fields[]`。卫生器具和生活热水设备以设备真实名称作图注；绿化、其他、道路冲洗三类的基础图注分别为“绿化灌溉设施”“其他用水设施”“道路冲洗设施”；多图片字段时再追加字段名称。没有图片字段时不生成配图告警，也不阻断装配。

#### 4. 6.3 用热系统运行分析

##### 4.1 段1 热源与供暖方式

- 单一热源：`{单位简称}供暖采用{热源}，供暖末端为{末端}，采暖期为{起}至{止}。`
- 多栋建筑热源不同：按建筑分组写。
- 末端有多种：写"以{主末端}为主，部分区域采用{次末端}"；"精密空调室内机"统一写"空调室内机"。

##### 4.2 段2 计量与结算

- 按面积：`供暖按建筑面积计缴热费，供暖面积{面积} m²，供暖费单价{单价}元/m²，供暖费用{费用}万元。`
- 按热量：`供暖按热量计缴热费，安装热量表，热价为{单价}元/GJ。`
- 按面积计费不要求安装热量表或提供供热量。不得写"未安装热量表""供热量无法单独计量""热力实物量数据缺失"，也不得将其列为问题、待核实项或整改建议。
- 除按面积计费本身不要求的热量数据外，其他缺失项不编；确会影响结论时才用红字【待核实】。

##### 4.3 段3 热耗特点

- 按面积计费：只写已获取的供暖面积、计费单价和供暖费用，并分析热费趋势；不得要求供热量，也不得把无热量表写成数据缺口。
- 按热量计费且有供热量：写三年供热量与趋势；只有热费时，写三年供暖费用与趋势。
- 按热量计费但供热量、供暖费用均无记录：只写可核对的热源、末端和计费方式，不生成逐年热耗分析。

#### 5. 6.4 用燃气系统运行分析

##### 5.1 段1 气源与用气设备

- 写气源（管道天然气/液化石油气）与已获取信息的用气设备；
- 只写已获取信息的设备，不臆造食堂用气；
- 有服务区域的要写（如"布置于手术室区域，为消毒用蒸汽提供热源"）。

##### 5.2 段2 用气环节与运行

- 蒸汽锅炉：台数、服务区域、运行时间；
- 炊事：供餐时段、灶具数量（有登记才写）；
- 运行时间缺失不写具体时段。

##### 5.3 段3 用气特点与计量

- 三年用气量 + 趋势：单调上升/下降写"呈逐年上升/下降态势"，非单调按 5%/10%/15% 四档；
- 有气费补气费；
- 已登记设备之外如现场收资确认存在其他用气设备，应写明设备名称、用途和运行方式；未确认时正文不推测该项。

燃气/燃油锅炉、灶具等非生活热水系统表设备照片按 `photo_section_key=gas_system` 放在 6.4，不得留在 6.1 其他用电设备；生活热水系统表（`ts_institution_device_hotwater`）的设备照片统一放 6.2，即使其设备事实写在 6.4 也不得把照片留在 6.4。无图片字段时不生成配图告警，也不阻断装配。

#### 6. 6.5 其他用能系统运行分析

- 有汽油/柴油实物量、车辆数量 → 写具体数量与趋势；
- 只有费用 → 只写费用与趋势，**不写**"实物量/车辆数量未取得"这类缺口句；
- 无任何其他用能 → 不生成该节。

#### 7. 通用写作规则

1. 第6章只写事实与可验证评价；禁"建议/需/应/优化空间/浪费风险"等建议性措辞。
   "改造"仅在"建议改造/应改造/需改造"等祈使语境禁用；已完成的节能改造（如"2023年统一改造更换"）可如实陈述。
2. 无分项计量不得推断占比；无光效数据不得评价光效；无量化依据不得说"导致指标偏差"。
3. 表格缺值写"—"；正文只写有依据的事实和评价，字段为空时直接省略该项，不得把空值写成"无""未计量"或"缺失"。
4. **全报告禁用**"未登记""待平台补录""平台登记""系统数据"等内部管理/平台语言，也不得将其替换为
   "现场未获取到""资料未提供""需进一步核实"后当作事实结论。空值就是空值，正文省略；
   只有数据相互矛盾、异常值确需单位确认时，才写清具体矛盾并使用红字【待核实】。
5. 第6章**不引用第5章图表**，需要数据时直接写实算数值；第7章只引系统名，不引"6.1（2）"编号。
6. 数值：整数不带小数位，非整数保留两位，禁千分位；数值与单位之间空一格。

### 二、7.1.1 能耗监测系统（固定判定树）

先按“用电 → 用水 → 用燃气 → 用热”四类描述计量现状，再判断是否建设能耗监测系统。

#### 2.1 用电

数据：`metering.electric_meters`、`independent_aircon / independent_light_socket / independent_power / independent_special`、
`equipment[].independent_metering`（主要用能设备独立计量“有/无”）、`metering.ledger_text`（电表台账）。

> 分项计量状态按年份留档于 `metering.electric_metering_by_year`（`sub_metering` / `scenario`）。
> 取**审计期最后一年**的状态（例：审计期 2022—2024 取 2024，不是取最新的 2025）；
> 该年记录缺失时才回退相邻年份，并在正文说明口径。

主要用能设备范围：冷热源设备、供暖空调输配设备、医疗设备、生活水泵、单独照明、信息机房、厨房设备。

| 分支 | 条件 | 固定表述 |

| E1 | 仅总计量电表 | 本项目用电计量仅安装总计量电表，仅能对项目内总用电量进行计量。 |
| E2 | 有楼栋/区域电表，但未按四大分项计量 | 本项目用电除总表外，按楼栋/区域设置了计量电表，但未按空调、照明插座、动力、特殊用电四大分项计量，也未对主要用能设备独立计量，计量颗粒度较粗。 |
| E3 | 有四大分项，但无主要设备计量 | 本项目用电能够实现空调、照明插座、动力系统用电计量，但未对{特殊设备清单}等特殊设备独立计量，未对主要用能设备单独计量。 |

> 覆盖率 = 已独立计量的主要用能设备类别数 ÷ 本项目实际存在的主要用能设备类别数。

#### 2.2 用水

数据：

- `energy_meter`（`data_type=2` 水表）：`meter_count`、`measured_depth`（仅总表/楼栋/楼层/科室…）、
  `kitchen_water`（厨房用水单独计量 0/1）、`year_water_value`；
- `water_aux.greening[].is_metering`（灌溉是否单独计量）；
- `water_aux.other[].water_system` + `is_metering`（空调/供暖补水等其他特殊用水系统是否单独计量）；
- `water_aux.road`（道路冲洗，无单独计量字段时只写事实）。

**状态语义（强制）**：上述计量字段统一按三态处理——`0/否/无` = 明确未单独计量，
`1/是/有` = 明确已单独计量，空值/`None` = 本次没有该项计量状态证据。
空值只能省略该用途的计量结论，**不得**改写成"未单独计量""现场未获取到……资料"或"待核实"。

| 分支 | 条件 | 固定表述 |
|---|---|---|
| W1 | 仅总表 | 本项目用水计量仅安装总计量水表，仅能对项目内总用水量进行计量。 |

| W3 | 总表＋＞80% 楼栋有表；无楼层/科室；存在明确登记为 0 的厨房/空调供暖/灌溉用途 | 本项目用水计量除总表外，能够实现各楼栋用水单独计量，但未实现建筑各功能区用水独立计量；{逐个列举状态为 0 的用途}未分类计量。 |

> 只有本项目实际存在且计量字段明确的用途才进入正文；状态为空的用途整项省略。
> 禁止把“厨房用水、供暖空调用水、灌溉用水”机械串成一串后统一断言“未计量”。

#### 2.3 用燃气

用两张表判断燃气用途：

- **厨房炊事用气**：`ts_institution_device_special` 中厨房/食堂相关行 `has_gas_use=1`；
  该行 `is_metering` 判断厨房炊事用气是否单独计量（1=有，0=无，空=本次无状态证据）。
- **供冷供热用气**：`ts_institution_device_air` 中 `gas_value>0`，或设备名称含“燃气/溴化锂/锅炉”；
  该行 `is_metering` 同样按 1=有、0=无、空=省略处理。

判断：

- 两者都存在且均有明确的计量状态时，任一为 `0` → “本项目供冷供热用燃气与厨房炊事用燃气未实现分别独立计量。”
- 只有一项存在 → 只写该项设备及其明确状态；如设备是用于手术室消毒的燃气蒸汽锅炉且
  `is_metering=0`，写“燃气蒸汽锅炉用于手术室消毒，未单独计量。”
- `has_gas_use=0` 只表示该设备明确不使用燃气；空值不能据此判断“无此用途”。
  有燃气消费但用途记录为空时，**省略用途及计量结论**，不得生成“待进一步核实【待核实】”。
- 设备存在但 `is_metering` 为空时，只可客观写设备名称、用途和服务区域，不写“未单独计量”或核实占位。
- 蒸汽锅炉仅用于消毒/工艺时，单列在燃气设备中，不计入“供冷供热用气”。

#### 2.4 用热

- `heat_pay_type=按面积缴费` → “本项目供暖按建筑面积计缴热费。”已取得供暖面积、单价、费用时一并客观说明。
- `heat_pay_type=按计量表缴费` → “本项目供暖按热量计缴热费，已安装热量表。”
- `heat_meters=0` 不能单独推断计量缺陷。缴费方式未知时只写已确认的热源、末端和计费事实，不写“未安装热量表”或“供热量无法单独计量”。

#### 2.5 能耗监测系统

- `has_monitoring_system=false` → “本项目未建设能耗监测系统，日常能源数据主要依靠人工抄录，难以实时开展数据对标、异常排查和异常预警。”
- `true` → 如实写已建系统及覆盖范围。

### 三、7.1.2 起：问题卡片库

### 四、A/B/C 的内部用法

- A（数据异常）：只用于判断某张卡片是否有实算数据支撑；**不再单独成“数据异常”章节**。
- B（实锤）：字段为真（计量、围护、指标）。
- C（机会）：设备台账/现场事实。
- 逐月异常已在第5章展开的，7.1 只保留与系统卡片相关的结论，不重复抄数值。
