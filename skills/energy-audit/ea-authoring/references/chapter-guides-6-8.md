### 第6章总指南

#### 1. 章标题与主干

- 6.1 下用（1）（2）（3）编号；系统名不进目录；正文引用写"6.1 中的照明系统"。

#### 2. 6.1 用电系统运行分析

##### 2.1 动态系统与顺序

固定顺序：**空调与供暖 → 照明 → 办公设备 → 其他用电设备 → 特殊用能系统（信息机房与医疗设备合并）→ 变配电**。
没有的系统跳过，编号顺延。

| equipment.category / 设备 | 归入小节 |
|---|---|
| 空调、输配（冷冻/冷却水泵）、其他设备中的冷却塔 | （n）空调与供暖系统 |
| 照明 | （n）照明系统 |
| 办公 | （n）办公设备 |
| 动力（电梯、电开水器、生活水泵等） | （n）其他用电设备 |
| 特殊设备（信息机房）、医疗设备 | （n）特殊用能系统 |
| 变配电、变压器 | （n）变配电系统 |

##### 2.2 每个系统固定三段

1. **系统构成**：设备名称、数量、单台功率、服务范围；
2. **运行方式**：季节、时段、控制方式（有字段才写，缺失不写具体时段）；
3. **运行特点与评价**：实算数据，或"未单独计量，无法单独核算"。

图贴构成段后，表贴运行段后。章末不另设"运行评价"节。

##### 2.3 设备清单表（每系统一张）

列固定：

`序号 | 设备名称 | 品牌 | 规格型号 | 数量 | 单台功率（kW） | 运行时间`

- `equipment.spec` 按 `|` 拆分：含 kW/W → 单台功率（W 换算 kW）；`运行:` → 运行时间；
  **纯数字片段绝不进规格型号**；无品牌/型号写"—"。
- 数量取 `equipment.quantity`；为 0 写"—"。
- **合并键 = 设备名称 + 品牌 + 规格型号 + 单台功率 + 运行时间**；同名同键合并、数量相加；
  合并后按单台功率降序排列。
- 表题：`表6.X XX系统设备清单`，不带单位名；表号在章内连续。

##### 2.4 照片

- 每个合并后的设备表行插 1 张照片（同一条目多张时取 `img_ids` 数据顺序第一张）；
- 图注：`图6.X 设备名`，不带单位名；图号按实际插图顺序连续；
- 有 `img_ids` 却未插图 → V3 告警；确实没有照片不阻断。

#### 3. 6.2 用水系统运行分析

##### 3.1 段1 用水构成

固定开头：

> {单位简称}用水主要为生活用水（主要为清洗用水、卫生间用水等）[、灌溉用水][及空调供暖系统补水]。

- **灌溉用水**：`ts_institution_water_greening`（`data.json → water_aux.greening`）有有效内容才写；
  收资确认没有则不写。
- **空调供暖系统补水**：`ts_institution_device_other` 有"空调系统补水装置"才写：
  - 冷源为冷水机组、热源为市政供暖 → "空调供暖系统补水"；
  - 只有冷水机组 → "空调系统补水"；
  - 只有市政供暖 → "供暖系统补水"。
- 若冷热源只登记一项、怀疑漏填，先在收资阶段确认；确认没有的项不写。

##### 3.2 段2 生活给水方式

按 `ts_institution_device_power` 中"生活水泵"的 `config`（配置情况）判断：

| 配置情况 | 固定句式 |
|---|---|
| 生活水箱 + 无负压都有 | 生活给水系统分别采用市政自来水经生活水箱储存、生活水泵加压和无负压供水两种方式。 |
| 只有生活水箱 | 生活给水系统采用市政自来水经生活水箱储存、生活水泵加压的供水方式。 |
| 只有无负压 | 生活给水系统采用市政自来水无负压供水方式。 |
| 没有生活水泵 | 生活给水系统采用市政自来水直供方式。 |

⛔ 禁止"生活水箱+生活水泵加压方式"这类工程简写，禁止"+"号。

##### 3.3 段3 固定句

> 消防系统用水量较少，忽略不计。

##### 3.4 6.2 设备表

有生活水泵、补水装置等给排水设备时，附一张 `表6.X 给排水系统设备清单`，列仍按 2.3 的 7 列。

#### 4. 6.3 用热系统运行分析

##### 4.1 段1 热源与供暖方式

- 单一热源：`{单位简称}供暖采用{热源}，供暖末端为{末端}，采暖期为{起}至{止}。`
- 多栋建筑热源不同：按建筑分组写。
- 末端有多种：写"以{主末端}为主，部分区域采用{次末端}"；"精密空调室内机"统一写"空调室内机"。

##### 4.2 段2 计量与结算

- 按面积：`供暖按建筑面积计缴热费，供暖面积{面积} m²，热价为{单价}元/m²，未安装热量计量表，供热量无法单独计量。`
- 按热量：`供暖按热量计缴热费，安装热量表，热价为{单价}元/GJ。`
- 缺失项不编；影响结论时用红字【待核实】。

##### 4.3 段3 热耗特点

- 有供热量：写三年供热量与趋势；
- 只有热费：写三年供暖费用与趋势；
- 两者都没有：`供热量及供暖费用数据需进一步核实【待核实】，暂无法分析逐年热耗。`

#### 5. 6.4 用燃气系统运行分析

##### 5.1 段1 气源与用气设备

- 写气源（管道天然气/液化石油气）与已获取信息的用气设备；
- 只写已获取信息的设备，不臆造食堂用气；
- 有服务区域的要写（如"布置于手术室区域，为消毒用蒸汽提供热源"）。

##### 5.2 段2 用气环节与运行

- 蒸汽锅炉：台数、服务区域、运行时间；
- 炊事：供餐时段、灶具数量（有登记才写）；
- 运行时间缺失不写具体时段。

##### 5.3 段3 用气特点与计量

- 三年用气量 + 趋势：单调上升/下降写"呈逐年上升/下降态势"，非单调按 5%/10%/15% 四档；
- 有气费补气费；
- 已登记设备之外仍有明显用气用途时，写"其他用气设备情况需进一步核实【待核实】"，收资确认后删除。

#### 6. 6.5 其他用能系统运行分析

- 有汽油/柴油实物量、车辆数量 → 写具体数量与趋势；
- 只有费用 → 只写费用与趋势，**不写**"实物量/车辆数量未取得"这类缺口句；
- 无任何其他用能 → 不生成该节。

#### 7. 通用写作规则

1. 第6章只写事实与可验证评价；禁"建议/需/应/改造/优化空间/浪费风险"。
2. 无分项计量不得推断占比；无光效数据不得评价光效；无量化依据不得说"导致指标偏差"。
3. 表格缺值写"—"；正文缺失按"不写 / 红字【待核实】/ 事实说明"三级处理。
4. **全报告禁用**"未登记""待平台补录""平台登记""系统数据"等内部管理/平台语言；
   改用"现场未获取到""资料未提供""需进一步核实"。
5. 第6章**不引用第5章图表**，需要数据时直接写实算数值；第7章只引系统名，不引"6.1（2）"编号。
6. 数值：整数不带小数位，非整数保留两位，禁千分位；数值与单位之间空一格。

#### 8. 校验（V3）

1. 章标题必须为"第6章 主要能源资源利用系统分析"；
2. 6.1/6.2 必备；6.3/6.4/6.5/室内环境按条件生成；
3. 6.1 至少 3 个（n）小节，且与总述句一致；
4. 每个系统小节至少 3 段有效正文；
5. 设备表 7 列表头、表号连续；图注数=图片数、编号连续，有 `img_ids` 未用告警；
6. 禁词检查（含平台语言、建议类词）；
7. 第6章不得出现"详见第5章图…"类引用。

## 第7章 节能效果与节能潜力分析（原 chapter7-guide）

> 权威依据：烟台经济技术开发区人民法院正式报告 R7 版。

### 章节结构

```
第7章 节能效果与节能潜力分析

7.1 用能管理存在的主要问题
    [引导句：结合第5章指标分析、第6章系统分析与数据核查诊断结果，……主要问题如下：]
   （1）~（6）问题条（含数据异常类 3 条）

7.2 节能改进建议
    [引导句：针对上述问题，本着"管理节能、技术节能、行为节能并重"的原则，提出如下节能改进建议：]
  7.2.1~7.2.6 建议条（每条：建议名 + 具体措施 + 预计节能量；与问题的对应按**序号隐含**）
    [收尾段：综上，如上述建议全面落实，……预计年可节约……]
```

### 7.1 问题清单生成规则（问题数 = 数据异常类 A + 实锤类 B + 机会类 C）

问题条编号用 `（1）（2）（3）…`，三类问题混排，顺序 A → B → C：

> **★依据锚点（2026-09-29 用户定，决策 3-A；B/C 类用，A 类不用）**
> **能引就引、无则免**：B/C 类问题如有可援引的依据，**三选一**写一处——
> **标准条文**（标准名＋条文号＋摘引原文，融入句内）／**定量数据**（设备参数、装机容量、量级换算）／
> **设备原理**（相似定律、换热与能效一般规律）。**找不到依据就不写**，不加占位符、不硬凑、不判不合格。
> **四条纪律**：①融入句内，禁括注（`（出自…）`）与只报号（`依据 GB…`）；②每条最多引 1 部标准；
> ③**标题零条文**（7.1 标题句、7.2 的 `7.2.N` 小标题只写现象/措施名）；④先验适用条件——
> 例如 GB 55015 第 3.3.6 条须"面积≥20000 m² **且**集中空调"两个条件同时满足，且它属第 3 章
> **新建建筑设计**，对既有建筑**只能作参照/达标整改方向，不得写成"违反"**（运行期义务看第 7 章）。
> **锚点直接查表**：`ea-authoring/references/chapter7-anchor-table.md`（按 运行管理／既有改造设计／新建设计参照 三组整理，
> 附"常见问题 → 推荐锚点速配表"）。**查表，不现翻标准原文库**。机械闸：`ea-validation/scripts/check_chapter7_anchors.py`。

#### A. 数据异常类（从逐月/逐年数据诊断，V3 的数据核查诊断同源，必写有异常的项目）

> **★必读现成素材（2026-09-20 接入）**：`<项目>/diagnosis_chapter7_material.txt`（S3 datava V1 DATA_CHECK 产出）。
> 它已经把逐月/逐年异常**诊断好了**（问题标题 + 系统 + 严重程度 + 推断原因与置信度 + 验证方法 + 建议措施及节能率/回收期）。
> 契约 `_context.md` 第六节会列出条目摘要；**写 7.1 前必须打开原文**。
>
> **四条使用纪律**：
> 1. 「推断原因」是**候选**（带置信度）——必须用本项目台账/逐月数据验证后再写，**不得直接当结论**；验证不了写「疑似」并注明待核实。
> 2. 「建议措施」的节能率/投资级别/回收期是**通用区间**——写进 7.2 前须与本项目实际（设备型号/投资额/运行工况）对齐，或标注为参考区间。
> 3. `critical` / `warning` 的条目**必须**进 7.1，再按下方规则补实锤类；问题条数 = 数据异常类（素材）+ 实锤类。
> 4. 素材只覆盖 A 类（数据异常），**不能替代 B 类实锤问题**（计量/设备/围护结构）
>    与 C 类机会问题（系统与设备节能机会）。
>
> 素材不存在（S3 未跑）时：只能按下方规则从本项目数据自行归纳，并如实标注依据；**不得编造异常**。

| 异常类型 | 诊断规则 | 问题条模板 |
|---|---|---|
| 夏季空调用电异常偏高 | 三年 7-9 月电量明显高于其他月（8 月峰值 vs **全年月平均水平（含当月）** 偏高>50%） | "夏季空调供冷期用电异常偏高。2023年、2024年、2025年8月用电量分别为…kWh，较全年月平均水平分别偏高X%、Y%、Z%，连续三年在供冷高峰期出现显著尖峰。反映冷水机组及冷却塔散热效率下降，空调系统运行能效偏低。" |
| 供暖期燃气用量异常波动 | 逐月天然气个别月份偏离月均>±30%，取偏离最大的 2~3 个显著项 | "供暖期燃气用量异常波动。2024年11月天然气用量180m³（较月均偏低62.3%）、12月840m³（偏高75.9%）、…。燃气用量月度间波动大，供餐台账与用气记录未实现逐月核对，炊事用气管理不精细。" |

> 百分比与点名月份必须从逐月数据**实算**（用终端 python 算，禁心算），无异常则该项不写。

#### B. 实锤类（从 metering/equipment/buildings/指标数据推断，沿用旧版规则）

1. 分项计量与能耗监测缺失（metering.has_monitoring_system=false 或独立计量不足）："分项计量与能耗监测缺失。全院仅配置电表X只、水表X只，空调、照明、动力等系统未实现分项计量，信息机房未单独计量，无能耗监测系统。系统级能耗无法拆分核算，节能管理缺乏数据支撑。"
2. 照明设备老化、缺乏控制手段（荧光灯/吸顶灯占比高 + 无智能控制）："照明系统设备老化、缺乏控制手段。传统荧光灯、吸顶灯及大功率特殊灯具占比高，走廊、楼梯间照明无感应控制，存在"长明灯"现象，照明用电浪费。"
3. 人均指标对标超标（人均综合能耗/人均取水量高于约束/通用值，从 indicators 取数）："人均综合能耗、人均取水量对标超标。2023年—2025年人均综合能耗分别为…kgce/人，高于定额约束值…；人均机关取水量2023年、2024年为…m³/(人·a)，高于用水定额通用值…。用能人数少、人均分摊高是重要原因，但也反映节水节电仍有挖潜空间。"
4. 建筑围护结构（屋面保温=无 → 屋面未设保温问题；外墙保温=有则**禁止**提外墙保温问题）

#### C. 机会类（系统与设备节能机会；证据 = 设备台账或现场事实，2026-09-28 新增）

> 缘起：淄博一四八医院样板 7.1 的五条问题里，四条属"**系统与设备的机会**"——
> 空调与供暖智能化程度低（三座制冷机房人工手动调节、水泵工频）、可再生能源利用率低
> （除外科楼太阳能集热外无其他可再生、屋面与车棚未装光伏）、电梯存在节能空间
> （沿用出厂配置、未装动能回收）、未利用峰谷电价差（变压器闲置、无储能）。
> 这些**不是**"通用套话"（样板每条都带了现场可核查的事实），而本指南原先只开
> A/B 两类，A 类靠逐月实算、B 类靠字段为真，**都没有"机会"这条通道**，于是这类
> 问题在现行规则下要么写不出来、要么被"禁止罗列通用问题"误杀。

**两类侧写（与 B 类的区别）**：B 类说"**现状有问题**"（计量缺、灯具老化、屋面无保温）；
C 类说"**有可用但未用的机会**"（控制方式落后、设备未更新、未用可再生）。C 类结论落在
"存在节能空间"，B 类结论落在"管理盲区/指标偏保守"。

**证据形态**：C 类每条必须带**设备台账或现场事实**——型号、数量、配置、有无
（如"全院水泵均工频运行""未设置光伏发电系统"）。**无事实支撑的机会点不得写入**。

### 7.2 建议条生成规则（建议数 = 问题数，每条对应一条问题）

- 每条建议：`7.2.N 建议名` 标题 + 具体措施句群 + **预计节能量句**（允许"预计"表述，属节能潜力估算非实测数据）
  - **标题不写"（对应问题N）"**（2026-09-28 用户定）：对应关系按**序号隐含**——第 N 条建议对应第 N 个问题；
    如需明示，在措施句首写"针对{问题简称}……"，不进标题。
- 预计节能量表述示例（对齐正式版语气，比例区间从正式版参考值出发，结合本机构数据微调）：
  - 空调优化："预计可降低空调系统电耗3%~5%，节约电费2.5万元以上/年。"
  - 燃气管理："预计可节约天然气2%~3%，折合约0.15~0.22tce/年。"
  - 供暖调节："预计可降低热力消耗3%~5%。"
  - 分项计量："预计可促进综合能耗下降1%~2%。"
  - 照明改造："照明改造节电率一般可达15%~30%，按照明用电占非供冷期用电比重测算，预计年节电3万~5万kWh。"
  - 行为节能："行为节能措施投入小、见效快，预计可实现综合能耗、人均取水量同比下降2%左右。"
